\subsection{Analysis and Design}

\subsubsection{Database Schema}

Sprint 2 extends the database with asset and commerce tables: \texttt{assets} (with a JSONB \texttt{metadata} column for category-specific attributes), \texttt{asset\_tags}, \texttt{asset\_formats} (multiple downloadable formats per asset), \texttt{orders}, \texttt{order\_items}, \texttt{cart\_items} (stored in PostgreSQL for cross-device persistence), and \texttt{user\_downloads} (ownership records).

The Stripe integration uses the PaymentIntent pattern: the backend creates a PaymentIntent for the cart total and returns a \texttt{clientSecret}; the frontend confirms the card payment via Stripe.js (the card number never touches the backend); on success, the backend atomically records the order, unlocks the asset download, and dispatches a confirmation notification.

\subsection{Sprint Review --- Deliverables}

\begin{itemize}
  \item Asset catalog with filtering by category, price, free/paid status, and keyword search.
  \item Interactive 3D viewer for GLB/GLTF; specialized viewers for textures, HDRIs, and code files.
  \item Two-phase seller upload workflow: file upload to Supabase Storage, then metadata submission.
  \item Multiple file format support per asset.
  \item Persistent shopping cart stored in PostgreSQL with duplicate-ownership prevention.
  \item Stripe PaymentIntent integration with test mode validation.
  \item Order management with status tracking and automatic download unlocking.
  \item User library page showing all purchased and downloaded assets.
\end{itemize}

\subsection*{Conclusion}
Sprint 2 delivered the core marketplace functionality. Users can discover, preview, and purchase digital assets through a complete e-commerce flow. The 3D viewer and Stripe integration distinguish IGS Marketplace from simpler file-sharing solutions.
