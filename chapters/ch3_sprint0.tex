\section*{Introduction}
Sprint 0 constitutes the foundational preparation phase before any code is written. It encompasses market research, requirements elicitation, architectural decision-making, technology selection, and database design. The deliverables of Sprint 0 are the design artefacts and infrastructure choices that guide all subsequent development sprints.

% ---- 3.1 SYSTEM ARCHITECTURE ----
\section{System Architecture}

IGS Marketplace follows a \textbf{three-tier architecture} separating presentation, business logic, and data concerns. The two React + Vite SPAs (ports 5173 and 5174) communicate exclusively via a REST API with the Node.js/Express backend (port 3001), which in turn manages a PostgreSQL relational database and Supabase Storage for binary files.

The backend is internally structured around the \textbf{Routes → Controllers → Repositories} layered pattern with cross-cutting services (\texttt{storageService}, \texttt{auditService}, \texttt{aiService}, \texttt{tokenBlacklist}) used across multiple controllers.

% ---- 3.3 DATABASE DESIGN ----
\section{Database Design}

The complete database schema was designed in Sprint 0 and implemented incrementally through 18 numbered migration scripts. The schema is organized into six conceptual groups:

\begin{enumerate}
  \item \textbf{Identity \& Access:} \texttt{users}, \texttt{user\_roles}, \texttt{role\_permissions}, \texttt{audit\_logs}
  \item \textbf{Catalog:} \texttt{assets}, \texttt{categories}, \texttt{asset\_tags}, \texttt{asset\_formats}
  \item \textbf{Commerce:} \texttt{orders}, \texttt{order\_items}, \texttt{cart\_items}, \texttt{user\_downloads}, \texttt{subscription\_plans}, \texttt{user\_subscriptions}
  \item \textbf{Community:} \texttt{reviews}, \texttt{asset\_likes}, \texttt{notifications}, \texttt{groups}, \texttt{group\_members}, \texttt{trades}
  \item \textbf{Workspace:} \texttt{workspace\_tasks}, \texttt{projects}, \texttt{chat\_channels}, \texttt{chat\_messages}, \texttt{direct\_messages}
  \item \textbf{AI \& Events:} \texttt{user\_events}, \texttt{intern\_asset\_requests}, \texttt{intern\_vouchers}
\end{enumerate}

\section*{Conclusion}
Sprint 0 established the architectural blueprint, technology choices, and database design on which the entire platform is built. The schema and project structure defined here were adhered to consistently throughout all subsequent sprints, minimizing rework and enabling rapid iterative delivery.
