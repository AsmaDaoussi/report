The platform is used by external marketplace users and by internal IGS collaborators. Access
rights are controlled through a role-based access control model (RBAC), where each role
receives a set of permissions adapted to its responsibilities.

  \item \textbf{Visitor}
  \item \textbf{Member}
  \item \textbf{Intern}
  \item \textbf{Employee}

  \item \textbf{Super Administrator}
\end{itemize}

% ---- 2.2 NEEDS IDENTIFICATION ----
\section{Needs Identification}

\subsection{Functional Requirements}

\textbf{Common Features :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Authentication :} allow users to register, sign in and recover their account.
  \item \textbf{Profile Management :} allow users to view and update their personal information.
  \item \textbf{Asset Browsing :} browse the public catalog by category, search by name, and filter by criteria.
  \item \textbf{Asset Preview :} consult asset details and preview them in the browser or in VR/AR.
\end{itemize}

\textbf{Member :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Cart \& Checkout :} add or remove assets from the cart and proceed to payment.
  \item \textbf{Library :} access and download free or purchased assets.
  \item \textbf{Reviews :} rate, review and like assets.
  \item \textbf{Trade :} propose and respond to peer-to-peer asset exchanges.
  \item \textbf{Seller Request :} submit a request to become a seller.
  \item \textbf{Notifications :} receive notifications about orders, requests and moderation events.
\end{itemize}

\textbf{Seller :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Asset Upload :} publish assets with files, thumbnails, metadata and pricing.
  \item \textbf{Edit Request :} request modifications on already approved assets.
  \item \textbf{Creator Studio :} consult personal sales statistics and asset performance.
  \item \textbf{Support :} communicate with the moderation team via a ticketing system.
\end{itemize}

\textbf{Intern :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Asset Request :} request access to paid marketplace assets with a justification.
  \item \textbf{Voucher Redemption :} redeem vouchers issued by authorized staff.
  \item \textbf{Workspace :} collaborate through projects, tasks, and real-time chat.
\end{itemize}

\textbf{Employee :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Intern Request Management :} approve or reject intern asset access requests.
  \item \textbf{Workspace :} access projects, tasks, performance reports and team chat.
\end{itemize}

\textbf{Administrator :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{User Management :} manage users, roles, permissions and role upgrade requests.
  \item \textbf{Moderation :} approve, reject or hide submitted assets and intern uploads.
  \item \textbf{Platform Management :} manage categories, vouchers, commission rate and settings.
  \item \textbf{Analytics :} consult platform analytics, audit logs and order history.
\end{itemize}

\textbf{Super Administrator :}

\begin{itemize}[label=---,leftmargin=2em]
  \item \textbf{Audit Logs :} consult the full audit trail of all platform actions.
  \item \textbf{Role Configuration :} manage roles and their associated permissions.
  \item \textbf{Platform Settings :} control global platform configuration.
\end{itemize}

% ---- 2.3 NON-FUNCTIONAL REQUIREMENTS ----
\section{Non-Functional Requirements}

\textbf{Security :} the application must guarantee the confidentiality and integrity of user data. Access must be controlled based on roles and permissions, and all sensitive actions must be traceable.

\textbf{Performance :} the application must maintain a minimal response time and remain responsive even with large volumes of content and simultaneous users.

\textbf{Reliability :} the application must always be able to function correctly. Errors must be handled gracefully without disrupting the user experience.

\textbf{Scalability :} the system must be designed to support growth in users, assets and traffic without requiring major structural changes.

\textbf{Usability :} the system must be simple and intuitive to use. Navigation between pages must be smooth, and the interface must be accessible across different devices.

\textbf{Maintainability :} the architecture must make it easy to add new features, fix issues and apply updates without impacting the rest of the system.

\section{Project Architecture: 3-Tier}

The project follows a \textbf{three-tier architecture}: \\
Three-Tier Architecture, also known as three-layer architecture, organizes applications 
into three logical and physical layers: the presentation layer, the business logic layer, 
and the data access layer. This separation allows each layer to be developed, maintained,
and scaled independently, improving flexibility and reducing the risk of system-wide issues
when changes are made.
\begin{itemize}
  \item \textbf{Presentation Layer (UI Layer):} Handles the user interface and interaction, displaying data and capturing user input.
  \item \textbf{Business Logic Layer (Application Layer):} The core of the application where rules, workflows, and data processing occur.
  \item \textbf{Data Access Layer (Persistence Layer):} Manages storage, retrieval, and management of data, abstracting databases and external APIs from upper layers.
\end{itemize}
