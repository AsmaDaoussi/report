\chapterintro{%
This chapter covers the first two sprints of the project. Sprint~1 establishes the
security foundation: registration, sign-in, JWT issuance, OAuth callbacks and the full
RBAC layer, so that every subsequent feature can rely on a role-aware user context.
Sprint~2 delivers the complete public marketplace experience: a filterable asset catalog,
interactive 3D and WebXR immersive previews, a shopping cart, Stripe and Flouci payment
flows, and a personal download library protected by time-limited signed URLs. For each
sprint the chapter presents the scoped backlog, conception diagrams (use case, sequence,
class), realization screenshots and a sprint conclusion.%
}

\subsection{Sprint 1 Realization}

\paragraph{Authentication flow.}
Authentication is the entry point of any action that goes beyond public browsing. The
system supports three login methods: email/password, Google OAuth and GitHub OAuth. All
three paths ultimately produce a JWT stored in \texttt{localStorage['igs\_token']}. The
token is verified on every protected API call by the \texttt{authenticate} middleware,
which attaches a \texttt{req.user} object containing the user's ID, email, roles,
permissions and intern expiry date.

After a successful \texttt{POST /api/auth/login}, the backend:
\begin{enumerate}
  \item Verifies the password hash with \texttt{bcrypt.compare}.
  \item Checks the user's \texttt{status} (active / suspended).
  \item Signs a JWT with \texttt{jsonwebtoken} using \texttt{JWT\_SECRET}.
  \item Returns \texttt{\{ token, user \}} to the frontend.
\end{enumerate}

Logout is enforced by adding the token to an in-memory blacklist
(\texttt{services/tokenBlacklist.js}). On every subsequent request the \texttt{authenticate}
middleware extracts the Bearer token, checks the blacklist, verifies the signature, then
queries the DB for the full user record including roles and permissions. For intern
accounts, it auto-bans the user if \texttt{intern\_expires\_at} is in the past.

\paragraph{OAuth integration.}
OAuth flows use Passport.js strategies. After the provider redirects back to
\texttt{/api/auth/callback/:provider}, the backend upserts the user record and issues a JWT,
then redirects to the frontend with the token in the query string. The React callback page
(\texttt{Pages/Auth/AuthCallback.jsx}) reads the token, stores it and navigates to the
intended page.

\subsection{Sprint 2 Realization}

\paragraph{Categories and discovery.}
The marketplace supports thirteen asset categories: models, textures, HDRIs, shaders,
scripts, plugins, audio, VFX, 2D art, printables, animations, environments and decals.
Each category page passes a \texttt{category} prop to the shared
\texttt{<ItemsListing />} component, which fetches paginated results from
\texttt{GET /api/assets}. The catalog endpoint supports filtering by category, price range,
rating, file type, tags and sort order.

\paragraph{Asset detail page and 3D viewer.}
The asset detail page (\texttt{Pages/View.jsx}) renders an interactive preview adapted to
the asset type:

\paragraph{WebXR immersive preview.}
For compatible models, \texttt{Components/ModelViewer.jsx} enables immersive VR/AR
through the WebXR Device API: \texttt{renderer.xr.enabled = true} activates stereo
rendering and \texttt{VRButton}/\texttt{ARButton} are injected from
\texttt{three/examples/jsm/webxr/}. When \texttt{renderer.xr.isPresenting} is true, the
post-processing \texttt{EffectComposer} (Bloom and Bokeh passes) is bypassed because they
crash in XR stereo mode.

\paragraph{Asset access control.}
For each asset the backend computes an access level string via
\texttt{GET /api/assets/:id/access}. The logic implemented in
\texttt{computeAssetAccess()} returns one of:

\begin{enumerate}
  \item \textbf{owned} --- already in the user's library.
  \item \textbf{free\_download} --- asset is free and the user is authenticated.
  \item \textbf{auto\_grant\_igs} --- IGS-owned asset, internal collaborator above intern.
  \item \textbf{requires\_request} --- IGS-owned paid asset; intern must request approval.
  \item \textbf{purchasable} --- paid asset, not yet purchased.
  \item \textbf{blocked} --- not authenticated or insufficient role.
\end{enumerate}

The platform supports two checkout paths:

\begin{table}[H]
\centering
\caption{Payment methods}
\begin{tabular}{|L{2.5cm}|L{5cm}|L{5.5cm}|}
\hline
\textbf{Method} & \textbf{Provider} & \textbf{Use case} \\
\hline
Stripe & Stripe Inc.\ (international) & Credit/debit card payments \\
\hline
Free   & Internal (no gateway)        & Zero-price assets, instant unlock \\
\hline

Every paid sale records the commission split in \texttt{order\_items}: \texttt{commission\_rate}
(platform rate read from \texttt{platform\_config}, default 15\%), \texttt{commission\_amount}
(absolute amount kept by IGS) and \texttt{seller\_net\_amount} (amount remitted to the
seller). The Stripe webhook endpoint listens for \texttt{payment\_intent.succeeded} events,
updates the order status to \texttt{paid}, grants download access and triggers in-app
notifications.

\paragraph{Secure file delivery.}
Asset files are stored in Supabase Storage across two buckets: \texttt{assets-images}
(thumbnails, public, 10 MB max) and \texttt{assets-files} (3D models, ZIPs, scripts,
private, 500 MB max). The \texttt{assets} table stores \texttt{file\_path} and
\texttt{file\_bucket} rather than a public URL; the repository layer reconstructs the URL
at SELECT time. When a user requests a file via
\texttt{GET /api/assets/:id/download-url} the backend re-checks the access level, calls
\texttt{storageService.createSignedDownloadUrl(bucket, filePath, 3600)} to generate a
one-hour signed URL, and audit-logs super-admin overrides as
\texttt{SUPERADMIN\_OVERRIDE\_DOWNLOAD}.

\subsection{Sprint 2 Conclusion}
At the end of Sprint~2 the public marketplace is fully functional: visitors can browse

\section*{Conclusion}
This chapter delivered the authentication backbone and the commercial heart of the
marketplace. Sprint~1 ensured every subsequent request is authenticated and
role-controlled; Sprint~2 turned the platform into a usable storefront with a rich 3D
preview, a Stripe-powered checkout and a secure library. The next chapter covers
Sprint~3 (seller workflow: upload, moderation, reviews, Creator Studio, trades) and
Sprint~4 (the internal IGS Workspace). AI-driven features are presented separately in
Chapter~5.
