\section{Sprint 1: Platform Foundation}

\subsection*{Introduction}
Sprint 1 establishes the technical foundation of the platform: a fully operational Express.js server with PostgreSQL, a complete authentication system (JWT + OAuth2), and a six-level Role-Based Access Control layer. The React frontend skeleton is also initialized with authentication and permissions contexts.

\subsection{Analysis and Design}

\subsubsection{Authentication Flow}

The authentication flow operates as follows: the client authenticates with Firebase (email/password or Google OAuth2); Firebase returns a signed ID token; the client sends the token in every subsequent API request; the backend middleware verifies it via the Firebase Admin SDK; and if the user does not yet exist in PostgreSQL, a record is automatically created with the default \textit{member} role.

\subsubsection{RBAC Architecture}

The permission system is built on two database tables: \texttt{user\_roles} and \texttt{role\_permissions}. A custom middleware checks whether the authenticated user's role holds the required permission before granting access to any protected route. The six roles are ordered by privilege level: \textit{super\_admin} (100) $>$ \textit{admin} (80) $>$ \textit{employee} (60) $>$ \textit{intern} (40) $>$ \textit{seller} (20) $>$ \textit{member} (10).

\subsection{Sprint Review --- Deliverables}

\begin{itemize}
  \item Express.js server with full middleware stack (CORS, body parser, error handler, audit logger).
  \item PostgreSQL schema with core tables (\texttt{users}, \texttt{categories}, \texttt{audit\_logs}) and RBAC permission tables.
  \item Email/password and Google OAuth2 authentication flows with Firebase Admin SDK.
  \item RBAC middleware protecting all sensitive API endpoints.
  \item React frontend with \texttt{AuthContext}, \texttt{PermissionsContext}, and \texttt{ProtectedRoute} component.
  \item User profile page with view and edit capability.
\end{itemize}

\subsection*{Conclusion}
Sprint 1 delivered the foundational infrastructure on which all subsequent features are built. The authentication system, RBAC layer, and database schema are stable and extensible.
